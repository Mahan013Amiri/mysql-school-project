# پروژه‌ی MySQL مدرسه

[English](README.md)

یک برنامه‌ی ترمینالی کوچک CRUD (با پایتون) که به یک **سرور MySQL 8.4 روی یک ماشین لینوکسی جدا** وصل می‌شود. هدف این پروژه خود برنامه نیست، بلکه نشان دادن این است که چطور یک دیتابیس راه دور را **امن** راه‌اندازی و وصل کنیم، و دلیل هر تصمیم امنیتی چیست.

## معماری

```
 Windows (client)                                   Kubuntu 26.04 VM (server)
 ┌──────────────────────┐                          ┌─────────────────────────────┐
 │ app.py (Python)      │      TCP 3306            │ ufw firewall                │
 │ mysql-connector      │ ───────────────────────► │  allow only 192.168.35.1    │
 │ .env (secrets)       │   VMware NAT (VMnet8)    │ MySQL 8.4                   │
 │ 192.168.35.1         │                          │  bind-address 192.168.35.128│
 └──────────────────────┘                          │  user school_app@192.168.35.1│
                                                   └─────────────────────────────┘
```

| سیستم | نقش | IP (خصوصی، VMware NAT) |
|---|---|---|
| ویندوز (میزبان) | کلاینت: کد، گیت، پایتون | `192.168.35.1` |
| ماشین مجازی Kubuntu | سرور: فقط MySQL | `192.168.35.128` |

هر اتصال باید از چهار بررسی مستقل و به این ترتیب عبور کند:

1. **فایروال (ufw):** آیا بسته از IP مجاز به پورت مجاز می‌رسد؟
2. **اتصال شبکه‌ای (`bind-address`):** آیا MySQL روی این کارت شبکه گوش می‌دهد؟
3. **هویت:** آیا کاربری با این نام، **و** برای این میزبان، با این پسورد وجود دارد؟
4. **دسترسی (`GRANT`):** آیا این کاربر اجازه‌ی اجرای این دستور روی این دیتابیس را دارد؟

## تصمیم‌های امنیتی

| تصمیم | دلیل | اگر نمی‌کردیم |
|---|---|---|
| `bind-address` روی IP خودِ سرور | MySQL فقط روی یک کارت شبکه گوش می‌دهد | `0.0.0.0` یعنی گوش دادن روی همه‌ی کارت‌های شبکه‌ی سرور |
| `mysqlx-bind-address` روی `127.0.0.1` | پورت پروتکل X لازم نیست، پس داخلی می‌ماند | یک سرویس بی‌استفاده در معرض شبکه |
| کاربر `school_app@'192.168.35.1'` | هویت به سیستم کلاینت گره خورده است | `'%'` اجازه می‌دهد هر سیستمی برای ورود تلاش کند |
| `ufw allow from <IP کلاینت> to any port 3306 proto tcp` | فقط یک کلاینت به پورت می‌رسد | پورت باز، کل شبکه را به حمله‌ی حدس پسورد دعوت می‌کند |
| `GRANT SELECT, INSERT, UPDATE, DELETE` روی یک دیتابیس | حداقل دسترسی | باگ یا SQL injection می‌تواند جدول‌ها را `DROP` کند یا به دیتابیس‌های دیگر دست بزند |
| `.env` در `.gitignore` و `.env.example` در گیت | رازها از تاریخچه‌ی گیت دور می‌مانند ولی قالب به اشتراک گذاشته می‌شود | پسورد لورفته برای همیشه در تاریخچه می‌ماند و باید عوض شود |
| `%s` در همه‌ی کوئری‌ها | کوئری پارامتری | SQL injection |
| root با `auth_socket` و مدیریت با `sudo mysql` | پسوردی برای دزدیده شدن از شبکه وجود ندارد | حساب root قابل استفاده از راه دور |
| `mysql_secure_installation` با اعتبارسنجی پسورد (MEDIUM) | پسوردهای ضعیف رد می‌شوند | پسوردهای قابل حدس |
| `ufw allow ssh` قبل از روشن کردن فایروال | جلوگیری از قفل شدن بیرون سرور راه دور | از دست رفتن دسترسی به سرور |

**دفاع چندلایه:** اگر یک لایه ضعیف شود، لایه‌های دیگر هنوز خسارت را محدود می‌کنند. مثلاً حتی اگر فایروال برای همه باز شود، یک غریبه هنوز در لایه‌ی هویت رد می‌شود (خطای 1045).

## خواندن خطاهای اتصال

| خطا | معنی | لایه |
|---|---|---|
| `2003 Can't connect to MySQL server` | در را پیدا نکردم یا بسته بود | فایروال / `bind-address` / روشن نبودن MySQL |
| `1045 Access denied for user` | در باز شد ولی راهم ندادند | هویت (کاربر، میزبان یا پسورد اشتباه) |
| `1142 command denied` | وارد شدم ولی این دستور مجاز نیست | دسترسی (`GRANT`) |
| `1062 Duplicate entry` | محدودیت `UNIQUE` ردیف را رد کرد | داده (خطای امنیتی نیست) |

## راه‌اندازی

### ۱. سرور (Kubuntu)، در ترمینال

```bash
sudo apt update
sudo apt install mysql-server
sudo mysql_secure_installation
```

MySQL را فقط روی IP خودِ سرور گوش‌به‌زنگ کن. اول از فایل پشتیبان بگیر، بعد آن را ویرایش کن:

```bash
sudo cp /etc/mysql/mysql.conf.d/mysqld.cnf /etc/mysql/mysql.conf.d/mysqld.cnf.bak
sudo nano /etc/mysql/mysql.conf.d/mysqld.cnf
```

```ini
bind-address         = <IP_سرور>
mysqlx-bind-address  = 127.0.0.1
```

```bash
sudo systemctl restart mysql
sudo systemctl enable mysql
sudo ss -tlnp | grep 3306        # باید <IP_سرور>:3306 را نشان بدهد
```

دیتابیس و کاربر محدود را بساز (پسورد قوی را خودت انتخاب کن و هرگز commit نکن):

```bash
sudo mysql < schema.sql
sudo mysql
```

```sql
CREATE USER 'school_app'@'<IP_کلاینت>' IDENTIFIED BY '<پسورد-قوی>';
GRANT SELECT, INSERT, UPDATE, DELETE ON school_db.* TO 'school_app'@'<IP_کلاینت>';
SHOW GRANTS FOR 'school_app'@'<IP_کلاینت>';
```

فایروال، فقط برای کلاینت باز شود:

```bash
sudo ufw allow ssh
sudo ufw allow from <IP_کلاینت> to any port 3306 proto tcp
sudo ufw enable
sudo ufw status numbered
```

### ۲. کلاینت (ویندوز، CMD)

```
git clone <آدرس-این-ریپازیتوری>
cd mysql-school-project
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

فایل `.env` را باز کن و مقدارهای واقعی را بنویس (مخصوصاً `DB_PASSWORD`). این فایل توسط گیت نادیده گرفته می‌شود.

```
python app.py
```

## چه یاد گرفتم

- یک اتصال از چند لایه‌ی مستقل عبور می‌کند و کد خطا (2003 در برابر 1045 در برابر 1142) نشان می‌دهد کدام لایه آن را رد کرده است.
- در MySQL هویت یعنی **کاربر + میزبان**. `school_app@localhost` و `school_app@'192.168.35.1'` دو حساب کاملاً جدا هستند.
- `bind-address` مربوط به **سرور** است (کجا گوش بدهد) و میزبانِ کاربر مربوط به **کلاینت** (چه کسی اجازه‌ی ورود دارد).
- حداقل دسترسی، خسارت باگ و injection را محدود می‌کند.
- گیت تاریخچه را برای همیشه نگه می‌دارد، پس رازِ لورفته باید «سوخته» فرض شود و عوض شود، نه فقط حذف.
- IP دینامیک می‌تواند `bind-address` را خراب کند؛ برای راه‌اندازی بلندمدت باید IP سرور ثابت شود.
